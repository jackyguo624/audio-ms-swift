# FireRed AISHELL-1 退化原因：组件干预与证据分级

**更强的证据把本次退化定位到已训练出的 LLM LoRA 增量。** 我们补做了两个完整官方测试集的组件交叉推理：只替换 LLM 即得到 849 个字错，接近完整 SFT 的 850；只替换音频侧是 812，原始模型为 804。105 条原始→完整 SFT 的退化句中，有 96 条只换 LLM 就得到与完整 SFT 完全相同的规范化输出。

这定位了当前已保存权重的主要影响组件；仍需区分“组件权重变化在哪边复现退化”和“哪项训练设置导致了不合适的权重变化”。后者不是这两个推理实验就能完全证明的。

## 1. 实测组件交叉结果

这里的“音频侧”包含 encoder 和 projector；“原始 LLM”已合并官方 ASR 预训练增量，“SFT LLM”再合并本项目 checkpoint-7507 的新 LoRA。没有重新训练。

| 组合 | 音频侧 | LLM | 字错误数 | CER | 相对原始净字错变化 |
| --- | --- | --- | ---: | ---: | ---: |
| A | 原始 | 原始 | 804 | 0.7674% | 0 |
| B | 原始 | SFT LoRA | 849 | 0.8104% | +45 |
| C | SFT | 原始 | 812 | 0.7751% | +8 |
| D | SFT | SFT LoRA | 850 | 0.8113% | +46 |

四组均为完整 7,176 句、104,765 个参考字符、BF16/SDPA、batch 16、greedy、512 新 tokens、seed 42、同一提示及评分规则。A/D 沿用已审核的原始/完整 SFT 结果；B/C 是新增单卡 GPU 推理。新 loader 复用原音频特征、prompt、mask、generate 和评分路径，仅改变权重加载子集。

两个新实验都完整 hash 了实际加载的参数与 buffer：未选中的模块保持逐字节相同，选中的模块确有变化；LLM-only 的 392 个新 LoRA tensor、audio-only 的 554 个 encoder/projector 参数逐项正确加载。4 项真实 tiny FireRed+PEFT CPU 隔离测试，以及两组完整测试的独立逐句 DP、覆盖、配置和源哈希检查均通过。

### 条件效应与耦合

- 原始音频侧固定，替换 LLM：`B−A = +45` 字错；SFT 音频侧固定，替换 LLM：`D−C = +38`。
- 原始 LLM 固定，替换音频侧：`C−A = +8`；SFT LLM 固定，替换音频侧：`D−B = +1`。
- 净错误数交互项为 `D−B−C+A = −7`。这些是条件净差，不能将 `45/46` 当作逐字符错误原因的分配比例。

LLM-only 与完整 SFT 有 7,140/7,176 句输出完全相同；在 105 条退化句中相同 96 条。其中 89 条同时满足“LLM-only 复现完整 SFT 输出，audio-only 保留原始输出”。按是否比原始句错误数更多分组：92 条只有 LLM-only 单独变差，7 条两种单独替换都变差，6 条单独替换均未变差、组合后却变差。没有 audio-only 单独变差而 LLM-only 不变差的退化句。

20 个配对说话人 cluster 重采样 20,000 次（seed 20261014），CER 差的 95% percentile 区间如下，单位为百分点：

| 对比 | 点估计 | 95% 区间 |
| --- | ---: | ---: |
| B−A：只换 LLM vs 原始 | +0.0430 | +0.0067 ～ +0.0799 |
| C−A：只换音频 vs 原始 | +0.0076 | −0.0048 ～ +0.0229 |
| D−B：完整 vs 只换 LLM | +0.0010 | −0.0086 ～ +0.0105 |

这进一步支持 LLM 替换是更大的固定 checkpoint 影响。音频侧的小差异及交互项仍有不确定性，不能称音频“无影响”。这些区间描述测试说话人构成的重采样敏感性，不是训练方差。

## 2. 具体错误怎样随组件迁移

表中展示关键变化语段，最后一列为四组的整句字错数。

| 样本 ID | 原始 / audio-only | LLM-only / 完整 SFT | A / B / C / D 字错 |
| --- | --- | --- | ---: |
| BAC009S0913W0309 | 美芝／威灵 | 每只／微零 | 0 / 4 / 0 / 4 |
| BAC009S0765W0226 | 寅吃卯粮 | 饮鸩饱粮 | 1 / 4 / 1 / 4 |
| BAC009S0915W0458 | 大煞风景 | 大厦封顶 | 1 / 4 / 1 / 4 |
| BAC009S0765W0447 | 二三岁 | 二十三岁 | 0 / 1 / 0 / 1 |
| BAC009S0901W0187 | 显着 | 显著 | 0 / 1 / 0 / 1 |
| BAC009S0905W0453 | 重监护室 | 重症监护室 | 0 / 1 / 0 / 1 |
| BAC009S0766W0381 | 募集丝巾 | 募集资金 | 2 / 0 / 2 / 0 |

相同的原始音频参数和特征下，仅换 LLM 就出现这些变化，说明相关文字决策转移发生在更新后的 LLM 条件解码函数中。LLM 既整合语音 embedding，也提供文字上下文先验；本实验尚不能把这两种内部作用进一步分开。资金等改善同样随 LoRA 迁移，说明它同时带来收益和损失。

耦合反例 `BAC009S0905W0196`：原始、LLM-only、audio-only 都输出参考中的“鉴借”，均为 0 错；只有完整 SFT 输出“借鉴”，记 2 错。因此部分具体变化需要两个组件共同变化才出现。

## 3. 可能促成这些错误的机制

### 较有支持：监督适配使已有字词决策边界移动

官方技术报告描述了大规模 ASR 训练，并报告 AISHELL-1 CER 约 0.76%；其 LLM 目标是转写部分的交叉熵。这提供了继续适配一个已经较强的 ASR 模型的背景，并不说明本地权重的具体预训练样本。[FireRedASR 技术报告 §2.2、表 2](https://arxiv.org/html/2501.14350v1)

本次原始 CER 已为 0.7674%。新 LoRA 虽保留了基座原参数，仍会改变整个解码函数；当前 SFT 目标没有显式要求在训练未覆盖的样本上保留原始输出。对近音词、专名等分数接近的候选，参数变化可能翻转选择。美芝和威灵在这 120,098 条训练目标中均出现 0 次，但在测试参考中出现 9/13 次；原始输出均识别到，完整 SFT 仍保留 8/12 次。这与局部上下文决策漂移相容，尚不能称作这些词的全面遗忘。

这个机制是对现象的解释假设。组件实验确认“改变哪个模块的权重能复现退化”，没有直接测量注意力、候选 logit margin 或建立语义知识遗忘的证据。

### 部分支持：转写写法、标注风格与 CER 目标之间有张力

精确子串计数显示：

| 写法对 | 训练出现次数 | 相关观察 |
| --- | ---: | --- |
| 借鉴 / 鉴借 | 27 / 0 | 完整 SFT 把该测试句参考的鉴借改为借鉴，属于组件耦合例子 |
| 重症监护室 / 重监护室 | 12 / 0 | 只换 LLM 即把参考重监护室补为重症监护室，增加 1 错 |
| 债券 / 债劵 | 171 / 35 | 测试输出债劵从原始 0 次增加到 SFT 10 次；参考写法不同会产生改善或退化 |
| 资金 / 丝巾 | 790 / 0 | 只换 LLM 即把募集丝巾改为募集资金，修复 2 错 |

这些相关证据能解释部分写法变化，却不是统一的词频因果规律。反例：训练中显着 46 次多于显著 12 次，SFT 输出却转向显著；账户 116 次多于帐户 8 次，仍出现反向变化。饮鸩饱粮、大厦封顶、微零、李冰冰在训练文本中均为 0 次，不能将这些错误解释为完整背下了训练中的错误短语。

未听音或审定参考，不能宣布哪种写法更忠实。固定字级 CER 奖励与当前参考一致，包括参考中的特殊词形；这些口径敏感 case 与可见的内容替换应分开解释。

### 值得优先对照：LLM 更新幅度与实际正则化设置

实际训练参数为 752,756,320：encoder 710,543,968、projector 22,027,264、新 LLM LoRA 20,185,088。音频侧占训练参数约 97.32%，但参数数量占比不能用作性能影响占比。

LLM LoRA 实际学习率为 `1e-4`，音频两模块为 `1e-5`，`r=8`、`alpha=32`。日志只显示第一个音频参数组的学习率，不代表 LLM 错用了音频学习率；optimizer/scheduler 的五组状态保留了正确的 10 倍比例。

一个明确配置落差是：`args.json` 写着 `lora_dropout=0.05`，Swift 4.5.3 的 `lora_llm` 构造 `LoraConfig` 时未传该字段，实际新 LoRA dropout 为 **0.0**。encoder 原有 dropout 为 **0.1**，不能说整个模型没有 dropout。`freeze_vit/freeze_aligner=true` 也被该 tuner 的音频全量训练行为覆盖，与实际保存、更新参数一致。

LLM 的有效更新幅度和正则化是否适合这份语料值得优先对照，但目前没有降低学习率或改变 dropout 的受控训练实验，不能把任一绝对超参数宣布为已证实的根因。

### 已确认的训练设计限制：token loss 与自回归 CER 不一致

训练是在真实前缀下优化转写 token 的交叉熵；评测则由模型使用自己生成的前缀做 greedy 解码，并按字符编辑距离计算 CER。多数容易 token 的平均 loss 可以很低，少数专名或近音候选的 argmax 翻转仍会增加字错。因此低 loss 和高 teacher-forced token accuracy 不保证 CER 改善。

按现有训练日志窗口分段，loss 均值大致在 **0.0195～0.0208**，没有清晰的一路下降趋势。开发集只在 step 7507 对同一权重评测两次，loss 均为 **0.046542**；没有早期 dev loss/CER 轨迹，没有用 dev CER 选择 checkpoint，实际采用完成 1 epoch 的末步。于是“最后权重优于所有中间权重”尚无证据，也不能从 train/dev loss 的差直接断言过拟合。训练日志均值与最终开发集 loss 的聚合和模型时点不同。

## 4. 哪些解释在已检查路径中缺乏支持

- 全量 120,098 条 raw、normalized、prepared 目标逐条对齐，只去空白，没有额外改字、空目标、音频映射错误或目标特殊 token 污染。
- prompt 和 speech 的 labels 被 mask，响应和 EOS 受监督；训练/解码 chat 结构一致，解码没有输入参考文本。
- 音频占位严格对齐，原特征、mask、生成参数保持一致；两组模块参数隔离由实际全内容 hash 验证。
- 有有限梯度、非零 optimizer moments 和三模块实际权重变化。未见足以证明训练未更新、重复除梯度累积因子或学习率分组错误的证据。
- 音频权重及 Adam moments 为 BF16，新 LoRA 权重及 moments 为 FP32；无精度对照，数值精度只能列候选，且不能解释为已证实的主要原因。所谓 batch_norm 层实际为 LayerNorm，不支持“漏保存 BatchNorm running stats”的解释。

这些检查针对已审核路径，不保证所有潜在实现问题都被穷尽。

## 5. 后续验证优先级

依据已保存权重的结果，优先对照 **LLM 更新强度、让期望的 LoRA dropout 真正生效、以及用 dev CER 监控并选择 checkpoint**。仅保持原始音频侧、继续使用当前 LLM 增量仍有 849 错，因此音频冻结本身不足以消除这次已学得的退化。

要判断训练策略，应另做受控训练；本次组件替换不能预测“从训练开始就冻结音频”的结果。参考口径敏感 case 需回听/审校，保持官方固定口径主分数，额外规范化只能作为预先声明的副指标；避免用测试集选择配置或 checkpoint。
